# Gold Parser — как устроен бот (контекст для ИИ)

Этот документ объясняет устройство проекта **Gold Parser** максимально полно,
чтобы любой ИИ (например DeepSeek) мог понять, что делает бот, как он работает
и как его дорабатывать. Проект — на Python, живёт в папке
`C:\Users\skrob\OneDrive\Рабочий стол\Gold_Parser`.

---

## 1. Что делает бот (цель)

Бот ищет **объявления о продаже радиодеталей и электроники, содержащих
драгоценные металлы** (золото Au, палладий Pd, платина Pt; серебро НЕ интересует),
на российских барахолках **Авито (avito.ru), Мешок (meshok.net), Юла (youla.ru)**
и на форуме-барахолке radiokot. Для каждого найденного лота бот:
1. распознаёт, что это за деталь (по справочнику `components.csv`);
2. подставляет ориентировочное содержание Au/Pd/Pt в миллиграммах на единицу;
3. по текущей цене за грамм металла (ЦБ РФ) считает **стоимость металла** в лоте;
4. считает **кратность** `ratio = стоимость металла / цена лота`;
5. лот «ВЫГОДНО», если `ratio >= 3 И металл >= 100 ₽` (это значит: металла в
   деталях минимум в 3 раза больше, чем заплатил) — цель пользователя — перекупка
   радиолома на аффинаж/перепродажу с профитом «×3 и больше».

Пример из жизни: объявление «Микросхемы К155,1533,142,580 серий» за 10 ₽,
а металла (Au) в них на ~332 ₽ → ratio = 33× → «ВЫГОДНО».

## 3. Главный алгоритм «найти и оценить лоты»

Команда `python app.py scan "микросхемы" --pages 3 --limit 50`:
1. открывает профиль uc-браузера каждой площадки из **`config.DEFAULT_SITES`**
   (по умолчанию **Авито + Мешок**; Юла закрыта для гостевого сбора — включается
   только флагом `--sites youla`);
2. для каждой площадки ходит по страницам выдачи:
   - Авито — по URL `?p=1,2,3...` (пагинация через параметр, НЕ скролл подвала);
   - Мешок — по `?search=запрос` (важно: параметр `search`, а не `searchString`);
   - Юла (если включена) — вводит запрос в поле + Enter, ссылки собирает через JS;
3. с каждой страницы вытаскивает карточки (заголовок, цена, ссылка) — селекторы в `board_uc.extract_lots()`;
4. каждый заголовок прогоняет через `scraper.lot_from_text()` → распознаёт деталь из справочника, ставит цену;
5. отбирает ТОЛЬКО лоты, где распознана конкретная деталь (`lot.parts`) — это «точно продажа детали с драгметаллами»;
6. `_make_report()` считает по всем металл/маржа/ratio, выводит таблицу и сохраняет CSV в `output/`;
7. `_print_good_links()` — блок «=== ВЫГОДНЫЕ — чистые ссылки ===», сортирует по ratio, выводит короткие ссылки (обрезаны от мусорных параметров) и сохраняет их в `data/good_links.json` (для кнопки «Открыть выгодные» в панели).
8. **Все распознанные лоты пишутся в историю** (`history.record_scan`) для статистики/экспорта.

## 4. КЛЮЧЕВОЙ МОДУЛЬ `board_uc.py` — как обходит антибот

Это сердце бота. Прямой HTTP (requests/curl_cffi) Авито/Мешок/Юла блокируют
(антибот, капча, JS-рендер). Рабочее решение — **настоящий браузер**:

### 4.1 undetected-chromedriver (uc)
Библиотека `undetected_chromedriver` — патченая версия Selenium, которая **не
светится как бот** (обходит `navigator.webdriver`, отпечатки и т.п.). Открывает
реальный Chrome в **видимом окне** (не headless — headless детектится).

### 4.2 Постоянный профиль (ключ к «капчу один раз»)
Для каждой площадки свой профиль в `data/chrome_<site>_profile`. Когда Chrome
впервые входит на Авито, Cloudflare может показать капчу «я не робот».
Пользователь кликает её **один раз вручную** — профиль сохраняет куку
`cf_clearance`, и дальше uc открывает площадку **автоматически, без капч**,
пока кука жива (часы–сутки). Cookies дублируются в `data/cookies_<site>.json`.

### 4.3 Важные детали
- **Версия браузера**: `uc.Chrome(..., version_main=CHROME_MAIN)` — передаём
  мажор установленного Chrome (сейчас **154**). Если не передать, uc скачает
  ChromeDriver под другую версию и упадёт с
  `SessionNotCreatedException: ChromeDriver supports Chrome 155, browser is 154`.
- **Сбор карточек**: из `driver.page_source` через BeautifulSoup. Для Авито
  карточки — `div[data-marker="item"]`, внутри `[data-marker="item-title"]`
  (название) и `[data-marker="item-price-value"]` / `meta[itemprop="price"]`
  (цена). Для Мешка — `a[class*="itemCard"]`, внутри `[class*="itemTitle"]`,
  `[class*="price"]`. Для Юлы — карточки виртуальные (Vue), `page_source` их НЕ
  содержит → собираем ссылки через `driver.execute_script(...)` (JS-запрос по
  `a[href*="youla.ru/"]` с исключением навигации).
- **Пагинация Авито**: `collect_lots` и `collect_many` для avito идут по
  `?p=1..max_pages`. ВНУТРИ страницы НЕ скроллим вниз (иначе «упирается в
  подвал») — скролл-догрузка делается только для youla. Лимит (`limit`) для
  avito срезается только в конце (`return lots[:limit]`), иначе сбор обрывался
  на 1-й странице (`if len(lots) >= limit: break` не должен стоять для avito).
- **`collect_many`** — для команд `hunt`: держит ОДИН uc-браузер на площадку и
  гоняет все поисковые ключи, меняя URL (не открывает окно на каждый ключ —
  иначе зависает и требует много капч). Для avito использует отдельную функцию
  `_collect_many_avito` (переход по страницам), для остальных — `_collect_many_scroll`.

### 4.4 Автоматизация (Блок 1: прокси, антикапча, ротация)
- **Прокси для uc**: `config.load_uc_proxy()` читает `data/proxy.txt` или `UC_PROXY`
  и передаёт в `uc.Chrome` через `opts.add_argument("--proxy-server=...")`.
- **Прогрев профиля** `warm_up(driver, site)`: перед поиском открывает главную,
  ждёт 3-5 с, скроллит 1-2 экрана — меньше шансов упереться в капчу на первом запросе.
- **Задержки** `human_delay(2.5..6.0)`: случайная пауза между переходами страниц —
  чтобы не быть ботом.
- **Ротация профилей**: в `collect_lots` при капче (нет карточек + маркер CF)
  автоматически закрывает браузер и рекурсивно пробует следующий профиль
  `chrome_<site>_profile_2`, `_3` (параметр `_profile_idx`).
- **Заглушка капчи** `solve_captcha(driver)`: точка входа под 2captcha/CapSolver
  (пока возвращает False, если нет `CAPTCHA_API_KEY`).

## 5. Цены драгметаллов (`prices.py`)

- Источник — **ЦБ РФ**: `https://www.cbr.ru/scripts/xml_metall.asp?date_req=ДД/ММ/ГГГГ`
  (коды: 1=золото, 2=серебро, 3=платина, 4=палладий; руб/грамм).
- Иногда ЦБ закрывает эндпоинт HTML-стеной → автоматический fallback на зеркало
  `cbr-xml-daily.ru`.
- Приоритет: ручная цена (`data/manual_prices.json`) → ЦБ → зеркало → кэш
  `data/metal_prices.json`. **Важно**: если кэш есть, сеть НЕ ходим (кэш-приоритет)
  — иначе ЦБ-пробы могут висеть (особенно через VPN). Серебро (Ag) в маржу НЕ входит.

## 6. Справочник деталей (`components.csv`) и матчинг

- Формат строки:
  `category;name;desc;au_mg;au_hi;pd_mg;pd_hi;pt_mg;pt_hi;note;confidence`.
  Значения — миллиграммы на ОДНУ единицу. `*_mg`..`*_hi` — диапазон; берём среднее.
- Сейчас **164 позиции** по 13 категориям: конденсаторы КМ (КМ-1..КМ-6, D, К10-17/43/47),
  транзисторы (КТ/2Т/ГТ/КП — СВЧ и мощные с Au), микросхемы (155/1533/142/580/564/561/134/133/КР1810/КР1831/555/530),
  реле (РЭС-9..80, РП, РКМ), разъёмы (СНЦ/РП/2РМ/2РТ/ГРППМ/ОНЦ), платы (кромки, бортовые),
  лампы (ЛГ/ГУ/магнетроны/клистроны/ИВ), резисторы (ПТ/СП), диоды, переключатели, СВЧ-элементы.
- Колонка **`confidence`**: `exact` / `estimate` / `wide` — насколько надёжно содержание
  (exact — из открытых справочников СССР, estimate — ориентир, wide — широкий диапазон).
- `Reference.best_match(заголовок)` — находит самую специфичную деталь по
  ключевым словам (коды моделей весят больше описания). Берём ОДИН лучший тип
  (консервативно, не суммируем несколько — чтобы не завышать).
- Количество «шт» в заголовке (например «100шт») умножает содержание (`Lot.qty`).
- `Part.confidence` читается из CSV (default "estimate" для старых строк).

## 7. Фильтры мусора (`scraper.py`)

Чтобы в отчёте не было хлама из Авито/Мешка:
- `looks_like_buy_ad(text)` — отсекает заявки СКУПЩИКОВ («покупаем/принимаем/
  скупка/не спешите выбрасывать/наш сайт»). Это не лоты на покупку.
- `_looks_unrelated(text)` — отсекает одежду/обувь/аксессуары/услуги/недвижимость
  («кроссовки», «джинсы», «монтаж», «гирлянды», «пайка» и т.п.).
- `_UNRELATED_WORDS`, `_INFO_WORDS`, `_BUY_WORDS` — списки слов-маркеров.

## 8. Веб-панель (`launcher.py` + `launcher.html` + `run.bat`)

- Двойной клик `run.bat` → стартует `launcher.py` (встроенный `ThreadingHTTPServer`
  на `127.0.0.1:8756`) → открывает браузер со страницей.
- Страница: тёмно-золотой стиль, кнопки:
  - **«Найти везде»** → `scan <запрос> --pages <глубина>` (Авито+Мешок+Юла),
    выпадающий список глубины 5/15/40/60/100/150/ВСЕ;
  - **«🎯 Найти всё выгодное»** → `hunt --pages <глубина>` (перебор всех ключей);
  - **«Открыть выгодные»** → JS читает `GET /good` (`data/good_links.json`) и
    открывает ссылки в новых вкладках;
  - кнопки «Цены», «Прайсы», «Монитор».
- Таймер прогресса: статус-строка `⏱ X мин Y c — поиск идёт...#`, обновляется
  каждые 0.5с.
- `launcher.py` POST `/run` выполняет `python app.py <аргументы>` через subprocess
  (белый список команд `{prices, uc, shops, monitor, boards, scan, hunt}`),
  возвращает последние 6000 символов вывода.

## 9. ПРОДАЖА: Telegram-бот, автопостинг, история (Блоки 2-4)

Проект превращён в продаваемый продукт (подписка). Основная платформа — **Windows
локально**, Telegram-бот продаёт доступ.

### 9.1 Telegram-бот-подписчик (`bot/telegram_bot.py`)
- Запуск: `python -m bot.telegram_bot` (polling). Токен из `data/tg_token.txt` или env `TG_TOKEN`.
- Команды: `/start`, `/subscribe` (выбор тарифа + оплата), `/good` (последние 10 сигналов из БД),
  `/scan <запрос>` (запуск `app.py scan` в подпроцессе, результат из `data/good_links.json`),
  `/stats`, `/settings` (порог ratio, ключевые слова).
- **БД** (`bot/db.py`, SQLite `data/users.db`):
  - таблицы `users` (tg_id, tariff, expires_at, settings), `signals` (лоты, привязанные к юзеру);
  - лимиты: **free** — 3 сигнала/день с задержкой 3 ч между ними, **pro** — мгновенно + ссылки;
  - `is_active`, `can_send`, `add_signal`, `recent_good`, `all_stats`.
- **Оплата** (`bot/payments.py`): тарифы 499/1199/3999 ₽ за 30/90/365 дн; `create_payment_link`
  и `verify_payment` — заглушки, точки входа под ЮKassa/Telegram Stars.

### 9.2 Автопостинг в закрытые каналы (`bot/poster.py`)
- Из монитора: `python app.py monitor --post-to <free_channel> --post-to-pro <pro_channel>`.
- **free-канал** — без ссылки, с задержкой 3 ч; **pro-канал** — со ссылкой, мгновенно.
- **Антидубль**: `data/posted.json` (ключ лота → timestamp), чистка старых записей (14 дней).
- Отправка через Telegram Bot API (`requests`), токен тот же.

### 9.3 История и статистика (`history.py`) + команды
- `data/history.db` — ВСЕ распознанные лоты (не только выгодные) пишутся при scan/hunt.
- `python app.py stats [--days N]` — всего лотов, выгодных, средний ratio, топ-5 по ratio, по площадкам.
- `python app.py export --format xlsx` (или csv) — выгрузка истории в `output/history_*.xlsx` (openpyxl).

## 11. Частые проблемы и их решения (важно для сопровождения)

1. **«Завис / ничего не работает»** → скорее всего накопились зависшие
   `python`/`chrome`-процессы (uc открывает много процессов; при прошлых абортах
   они остаются, грузят CPU, конфликтуют за общие профили). **Лечение**: убить
   все `python` и `chrome` перед запуском.
2. **uc-краш**: `SessionNotCreatedException: ChromeDriver supports Chrome 155,
   browser is 154` → передай актуальный `version_main` в `uc.Chrome` (`CHROME_MAIN`).
3. **Авито упирался в подвал** → не скроллить вниз на стр, а переходить по
   `?p=`; лимит не срезать на 1-й странице (срезать в конце).
4. **Мешок показывает всё подряд** → правильный URL `?search=...`, а не
   `?searchString=...` (тот игнорируется).
5. **Юла не отдаёт лоты ⇒ убрана из авто** → карточки Юлы виртуальные (внутренний
   GraphQL), гостевому браузеру не доступны; Юла включается только флагом `--sites youla`.
6. **Кодировка .py** → НЕ использовать PowerShell `Set-Content` (добавляет BOM,
   Python падает SyntaxError). Править через Edit/Write или .NET `WriteAllText` без BOM.
   Признак поломки — русские строки превращаются в кракозябры (маркеры капчи перестают работать).
7. **Капчу нужно кликнуть один раз на каждой площадке** — профиль
   `data/chrome_<site>_profile` запоминает; при смене сети/IP капча может вернуться
   (тогда сработает авто-ротация на профили `_2`/`_3`).
8. **Прокси для прямого HTTP** (`market.py`) не обязателен — рабочий путь браузер
   `board_uc.py`. Для uc прокси задаётся через `data/proxy.txt`/`UC_PROXY` (Блок 1).

Бот перезапускается просто (`python app.py ...`), живых api-ключей не требует
(ЦБ бесплатен, браузер локальный). Для продажи: токен бота, реальная оплата в
`bot/payments.py`, каналы в `--post-to*`, лендинг `index.html` (заменить `ВАШ_БОТ`).
